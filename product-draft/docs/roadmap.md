# Delivery roadmap

No time estimates until weekly learning time, baseline knowledge and pilot scope are known. Each stage uses explain → teach-back → small lab → reviewed spec/design → implement → demonstrate failure/recovery → record evidence. Teaching all concepts completely before touching code is unrealistic; agree on the depth required for each bounded slice and deepen it through experiments.

1. **Foundation (current):** separate skills repository, BMAD installation, working agreement, product brief, first spec. Exit: user can explain the delivery workflow and tenant/access model; settle ages, institute workflow and permissions. No feature implementation before that teach-back.
2. **Isolation slice:** Python API plus Next.js login/workspace route, PostgreSQL memberships and assignments, migrations, negative access tests and OTel request traces. Learn HTTP, sessions, transactions, composite keys, authorization, HLD/LLD. Exit: student and teacher access demonstrate allow and deny cases across two institutes. Identity provider/local test auth is a design decision before implementation.
3. **Evidence slice:** cohort/classes, goals, attempts and rubric-backed evidence, deterministic progress. Exit: progress can be explained without an LLM and evidence cannot be silently overwritten.
4. **Agent slice:** Python LangGraph with scoped tools, optional LangChain adapters, model budgets, checkpoints, teacher review, versioned publication and offline evaluations. Exit: insufficient evidence, injection, duplicate resume, timeout and revoked access are demonstrated. Add a single A2UI plan surface after a compatibility spike.
5. **Operations slice:** local Prometheus/Loki/Grafana plus trace backend, dashboards and failure alerts; backup/restore, CI and rollback. Terraform/IAM/S3 and short-lived compute lab with explicit cost estimate. Exit: a consented pilot readiness review, not a blanket production-ready label.
6. **Distributed labs:** Redis cache/rate limiter; Kafka with outbox, replay and duplicate delivery; gRPC deadlines and cancellation; WebSockets reconnect/revocation; Neo4j curriculum queries; MCP scoped tools; A2A task exchange. Each lab has a hypothesis, baseline comparison and failure exercise. Keep synthetic data and a teardown command. Promote separately when justified.
7. **Kubernetes lab and scale review:** local deployment, probes, rollouts, resource limits, network policy support and recovery. EKS comparison only after cost review. Use measured bottlenecks to decide service extraction and managed infrastructure.

Production release is a separate decision requiring load/capacity assumptions, tested tenant isolation, agent quality thresholds, data lifecycle decisions, recovery evidence, observability, deployment/rollback and an affordable operating model. The skills production-readiness checklist supplies the review prompts; it cannot certify readiness by itself.
