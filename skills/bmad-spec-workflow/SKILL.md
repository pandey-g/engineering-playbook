# Bmad Spec Workflow

Read `../../docs/bmad-integration.md`, the installed framework manifest and consumer working agreement. Discover version-correct commands from the installation; do not mix stable and preview instructions. If absent, report that BMAD is not installed rather than simulating an official command.

Choose the smallest useful BMAD capability for the current phase: discovery, product framing, architecture, bounded story or review. Use its conversation to elicit decisions; do not accept its suggestions as user choices. Keep canonical ownership in the consumer brief/spec/ADR and link supporting framework outputs.

Use `../../docs/workflow.md` as this repository's integration contract. Specifications define behavior; the framework helps develop and challenge them. Keep the learner's actual teach-back before implementation when required by the consumer. Do not run unattended loops, parallel agent teams or install extra modules just because they are available. Finish with actual artifacts, unresolved questions and the next bounded learning step.
