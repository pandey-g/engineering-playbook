# Learn Before Build

Read the consumer's learning agreement and active feature first. Identify the smallest concept the learner needs for this slice, then explain the mechanism with that product's request/data flow, a simpler alternative and a failure scenario.

Ask one or two diagnostic teach-back questions appropriate to the learner. Use `../../templates/learning-record.md` when a persistent record helps. Record only the learner's actual answer, distinguish unassessed gaps from observed gaps, and adapt the explanation. A worked example from AI is not a learner answer.

In a consumer that requires understanding before building, wait for the learner's explicit readiness before implementing dependent behavior. Continue independent research/specification work while waiting. Do not demand complete mastery of an entire technology: define bounded competence as explaining the mechanism, justifying a tradeoff and predicting/recovering from a relevant failure. A diagram or paper lab can establish initial understanding before code.
